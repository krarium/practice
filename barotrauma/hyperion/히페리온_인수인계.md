# 히페리온(Hyperion) 잠수함 제작 — 인수인계서

- 작성: 2026-10-01, 이전 작업 세션의 AI(Claude Code)
- 읽는 대상: 이 작업을 이어받을 AI. 사용자는 한국어로 지시하고 한국어 답을 원한다.
- 기준 파일: **`히페리온 - 베이스 6 (사용자 수정).sub`** (사용자가 외장을 직접 만든 최신본)

---

## 0. 먼저 알아야 할 것

1. **무엇을 하는가.** Barotrauma(1.13.4.0)용 플레이어 잠수함 "히페리온"(임시 이름)을 만든다.
   - 사용자는 게임 에디터로 직접 작업한다.
   - AI는 `.sub` 파일(gzip으로 압축된 XML)을 파이썬 스크립트로 고쳐서 새 버전을 만들어 준다.
2. **작업 순서.**
   1. 사용자가 지시한다. 가끔 최신 .sub를 업로드한다.
   2. AI가 새 버전 파일(`히페리온 - 베이스 N.sub`)을 만든다. 원본은 덮어쓰지 않는다.
   3. AI가 검사하고 보고한다.
   4. 사용자가 게임에서 테스트하고 수정한다.
3. **게임 실행 불가.** AI는 게임을 실행할 수 없다.
   - 동작은 공개 게임 소스(github.com/FakeFishGames/Barotrauma)로 확인한다.
   - 파일은 `tools/check_rules.py`로 검사한다.
   - 보고할 때는 "인게임 미검증"을 분명히 밝힌다.
4. **반드시 최신 사용자 파일에서 시작한다.**
   - 사용자가 에디터에서 저장하면 **모든 ID가 다시 매겨진다.**
   - 그래서 예전 단계 스크립트(`tools/build_base*.py`)는 ID가 맞지 않는다.
   - 예전 스크립트를 다시 돌리면 사용자의 수정이 모두 사라진다. 참고용으로만 읽는다.
   - 새 작업은 새 스크립트(예: `tools/build_base7.py`)로 한다. 입력은 최신 파일이고, ID는 `tools/analyze_sub.py`로 다시 찾는다.
5. **규칙.** 3장의 상시 규칙을 지킨다. 못 지키는 것은 반드시 보고한다(사용자 지시).
6. **미결 사항.** 사용자 답을 기다리는 질문은 9장에 있다. 새 작업을 시작할 때 관련 항목을 먼저 확인한다.

## 2. 만들고 있는 잠수함

### 2.1 사양
- **이름:** 히페리온(임시). 파일 안의 `name`은 버전마다 `히페리온 - 베이스 N`.
- **크기 지시 (사용자):** 가로 68~72m, 세로 22~23m. 그림판 스케치가 기준이다(`input/원본_스케치.png`).
  - 스케치의 생김새: 좌상단이 한 층 더 높음. 우측 중앙에 돌출부. 하단 중앙에 오목한 홈.
  - 빨간 네모 = 밸러스트: 원래 좌 3칸 + 우 2칸이었고, 지금은 좌 3칸 + 우 3칸.
- **현재 크기 (사용자 수정본):**
  - 외벽(shell): x −3516~3510, y −1008~1016 → **70.3 × 20.2m**.
  - 외장 장식 포함 저장 크기: `dimensions="8320,2810"` → **83.2 × 28.1m**.
- **티어/값:** tier 3, price 53078, class Undefined, 권장 인원 4~8, cargocapacity 44.
- **설명문:** `description`은 아직 "임시 골격. 외벽/내벽/헐만 배치됨."이다. 마무리할 때 바꿔야 한다.

### 2.2 크기 조사 결과 (사용자 두 번째 지시: "티어3 이후 운용 가능한 최대 크기")
**DE 바이옴과 티어 3 구매처** (`Biomes/Biomes.xml`)
- Cold Caverns: 최대 T1
- Europan Ridge: 기본 T1 (city, shipyard 등에서는 T2까지)
- Aphotic Plateau: T2
- The Great Sea: 기본 T2. 티어 3은 아래 장소에서만 판다.
  - city, shipyard: 종류 무관
  - military: Attack
  - research: Scout
  - pirateoutpost: Transport
- Hydrothermal Wastes: T3
- 엔드존: DE가 지형을 따로 정의하지 않아 바닐라 엔딩 레벨을 그대로 씀

**일반 해역은 크기 제약이 거의 없다**
- 근거: 바닐라 `Level.cs`.
- 메인 통로 폭이 잠수함 크기에 맞춰 넓어진다.
  - 계산: 도킹된 것 포함 외곽의 긴 쪽 × 1.3, 최대 16,000(160m).
  - 레벨 폭의 1/5을 넘지 못한다.
- 동굴과 사이드 터널은 폭이 1,000~6,000으로 고정이다. 그래서 동굴은 다이버나 미니볼로 다녀야 한다.

**진짜 한계는 엔드게임이다**
- 에디터 경고: `SubmarineClient.CheckForErrors`가 **가로 80m 또는 세로 32m를 넘으면 `TooLargeForEndGame`**을 띄운다.
  - 이 판정은 저장된 `dimensions` 값을 쓴다.
  - `dimensions`는 `CalculateDimensions(onlyHulls:false)`로 계산한다. 숨김 요소는 빠지고 포탑은 포함된다.
- 엔딩 레벨 지형 파일은 공개 소스에 없어 직접 재지는 못했다.
- 권장: **80×32m 안**, 여유를 두면 약 70×25m(바닐라 최대 Berilia 67.3×21.2m).
  - 미니볼 같은 도킹 잠수정까지 합친 크기가 중요하다.

**참고 잠수함 크기**
- Malachite 108.97×24.44m (가로 초과)
- Anaconda 63.4×14.2m
- Iroh 57.5×24.6m
- CA-1N 54.1×15.8m
- 오르카 2함 - 확장 45.1×15.8m

> ⚠ **현재 사용자 수정본은 83.2m라 이 경고에 걸린다.** 외장 장식 폭을 줄일지, 무시할지 사용자 판단이 필요하다(9장).

### 2.3 좌표와 층
- 단위는 100 = 1m. `rect="x,y,w,h"`에서 (x, y)는 **좌상단**이고 **y축은 위가 +**.
- 원점은 선체 중앙 근처다.
  - 베이스 3부터 원점이 처음 베이스 대비 약 (+2208, −576) 옮겨졌다.
  - 그래서 `tools/rooms.py` 같은 베이스2 시절 좌표는 옛 좌표다.
- 방향:
  - **왼쪽 = 선미.** 대형 엔진과 꼬리 장식이 있다.
  - **오른쪽 = 선수.** 우측 중앙 돌출부와 우측 도킹포트가 있다.
- **층 이름 (사용자 지시: "위에서부터 A B C D E F G층, 벨러스트는 G로 통합")**

| 층 | 헐 y 범위 | 비고 |
|---|---|---|
| A | 713 ~ 968 | 좌측 상단 돌출부에만 있음 (x −3468 ~ −1620) |
| B | 457 ~ 713 | |
| C | 200 ~ 457 | |
| D | −56 ~ 200 | |
| E | −312 ~ −56 | |
| F | −568 ~ −312 | |
| G | −960 ~ −568 | 밸러스트 탱크는 F~G 높이(−960 ~ −312) 전체를 쓰지만 "G층"으로 부름 |

- 층 높이는 256(2.56m)이다. 수평 대형 내벽 두께는 48이다.
- 헐 경계 규칙은 3장 R6.
- 사용자가 선체 왼쪽 바깥에 층 표시 문자 A~G(`labelscaptureitletter*`)를 붙여 놓았다.

**⑥ 베이스 업로드 + 베이스2 작업 지시**
> 자, 일단 베이스를 만들었어. 각 방은 버튼이 달린 문으로 구분되어있고, 이동해야하는 곳은 사다리로 구분되어있어.(벨러스트 탱크는 아직 사다리 배치 안함) 각 공간마다 라벨로 이름을 붙여놨고, 아직 라벨이 없는 곳은 용도가 정해지지 않은 곳이야.
>
> 가장 우선 너는 벨러스트탱크의 크기를 조정해줘. 높낮이는 조절하지말고, 벨러스트 탱크 1의 왼쪽 '대형 내벽 수직'과 벨러스트 탱크 2의 왼쪽 '대형 내벽 수직'을 옮겨서 아무 조작이 없을떄 제자리 높이 유지할 공간을 만들어줘. 그리고 사다리로 연결된 공간들 모두 지나갈 수 있는 공간을 내줘야해. 대형 내벽 수평을 좌우로 벌리고, 거기에 버튼이 달린 해치를 설치하는 방식으로. 아, 하나 주의할게 있는데 '하부 잠수정 도크'라고 된 곳은 함체 내부로 인식되면 안돼.  커스텀 해치 4개로 막혀있지만, 저긴 물은 항상 들어오게 해둘거야. 그거 감안해서 탱크 크기 조절해야해.
>
> 그리고 벨러스트탱크 1과 2의 크기가 서로 같게한 뒤, 각 벨러스트 탱크는 3등분 해야해. 총 6개의 벨러스트 탱크로 만들어줘. 내부에 펌프도 일단 추가해주고. 배선등은 아직 하지마. 벨러스트 탱크 안에 보면 대형 플랫폼이랑 버튼문 만들어놨지? 그걸로 내부 공간을 3등분 하는거야. 벨러스트 탱크 1은 좌측 상단에 사다리를 만들어서 탱크 공간으로 들어가게하고, 벨러스트 탱크 2는 우측 상단에 사다리를 만들어서 탱크 공간으로 들어가게 해야해.
>
> 그리고 사다리가 놓인 공간을 실제로 이동가능하도록 고쳐줘. 수평 대형 내벽의 경우 내가 지금 해둔거처럼, 렉걸리지 않게 그림자 생성을 끄고 최대 내구도는 150으로.
>
> 그 후 각 공간마다 함체(hull) 구분을 제대로 지어줘야해. 각 함체는 사이사이 빈공간 거의 없이 붙게. 다른 잠수함들처럼. 도킹 가능한 수평도킹포트는 좌상, 우상, 좌하, 우하 4개 있으니 이것도 이동가능하게 바꿔주고. 최우측 수직도킹 공간도 있으니 이것도 이동 가능하게.
>
> 그리고 다른 잠수함들 보면, 내벽과 외벽 모두 '마감'이라는 구조물을 통해 자연스럽게 연결된거처럼 보이도록 해뒀거든? 내 잠수함도 그렇게 마감도 확실하게 해줘.
>
> 그리고 이제 배경을 만들어줘야해. 위에서 우선 업로드했었던 바닐라 함선들과, 모드 함선들의 내부 모습을 모두 참고해서 기초 배경을 만들어줘야해.  용도가 정해지지 않은 곳은 단순한 복도처럼 만들어두고, 이름이 정해진 곳은 다 해당 파트의 컨셉에 맞게 배경을 조정해줘. 스프라이트 높이들도 제대로 검토해서 배경답게 보이도록 신경써주고. 그리고 상호작용 가능한 기계나 가구등 (조작 가능한 설비, 제작기, 분해기, 캐비닛등)은 추가하지말고, 대신 배경을 배경답게 보이게하기 위해서 (상호작용 없음, 손상되지 않음)등을 체크해두고 배경용으로 사용하는건 얼마든지 가능해.
>
> 외벽은 아직 만들지말고, 전기설비도 아직 잇지말고.

**⑦ 베이스 3 업로드 + 베이스4 작업 지시 (IS v0.4.0 업로드)**
> 전에 업로드했던 산업 가구 모드를 업데이트해서, 네게도 업로드할게. 그리고 히페리온 베이스도 약간 업로드를 해놨어.
>
> 자, 앞으로는 잠수함을 만들때 해당 규칙을 최대한 지켜. 지키지 못할 일이 있을땐, 보고하고 알려.
>
> 전기 동작을 구현하기 위해 모든 종류의 게이트를 적절히 사용할것.
> 모든 게이트는 내벽 안에 배치하고, 스프라이트 높이값을 가장 낮게 설정하여 가장 앞부분으로 보이게 할것. '게임에서 숨기기' 체크 하여 에디터에서만 볼 수 있고, 인게임에선 보이지 않도록 할것.
>
> 위에서부터 A B C D E F G층 (벨러스트는 G로 통합)
> 정중앙 상단부 커스텀해치 추가
>
> 모든 배선은 내벽, 외벽, 해치, 문을 타고 직각으로 이동. 또한 배선은 '게임에서 숨기기'를 체크하여 에디터 모드에서만 보이게 할것.
>
> 버튼 달린 문 추가하여 공간 구분 새로 해둔곳이 몇군데 있으니, 거기 맞춰서 새로 함체와 유격 수정할것.
>
> 각 방에 적혀있는 라벨은 '게임에서 숨기기' 체크가 되어있지 않은 라벨만 설계 판단용으로 쓸것. 숨기지 않은 라벨은 플레이어를 위한 라벨.
>
> B층 중앙에 커스텀 해치 1개 추가했으니 해당 커스텀 해치에 맞춰 상부 외벽 수정하고 정상적으로 도킹 가능하도록 할것.
>
> C층 중앙에는 함장실이 있음. 함장실 내부에는 2개의 항법 단말기가 있음. 우측 항법 단말기는 메인 단말기이며(태그 : main_terminal) 좌측 항법단말기(태그 : dock_terminal)는 도킹 전용 단말기임. 두 항법 단말기는 모두 잠수함의 방향제어가 가능하나, 두개가 동시에 켜져 있으면 명령이 충돌할 가능성이 있음. 그러므로 두 항법 단말기 중앙에 위치한 버튼(태그 : Terminal_change_button)를 사용해서, 누를때마다 사용하는 항법 단말기가 바뀌는 방식으로 변경. 한쪽 단말기가 켜져있을때는 다른쪽 단말기가 꺼져있어야함. 두 단말기는 각자의 사이에 있는 상태모니터를 함께 공유함. 이 잠수함은 기존 바닐라에서 사용하는 도킹 버튼은 아예 사용하지 않을 예정이며, 도킹 전용 단말기의 신호 1 ~ 신호 6 버튼을 도킹 버튼으로 대체할 예정. 각 버튼의 이름도 바꿔줄것. 신호1 = 좌측 상단 도킹, 신호2 = 중앙 상단 도킹, 신호3 = 우측 상단 도킹, 신호 4 = 우측 중앙 도킹, 신호 5 = 좌측 하단 도킹, 신호 6 = 우측 하단 도킹. 도킹포트가 도킹 상태가 아닐땐 도킹하라는 신호를 보내고, 도킹 중일땐 도킹을 해제하라는 신호를 보내게 설정. 각 도킹 포트에 붙어있는 커스텀해치는 해당 도킹포트가 도킹상태일 경우 열리고, 도킹 상태가 아닐경우 닫힘. 메인 항법단말기는 아직 용도가 다 정해지지 않았음.
>
> C층~D층에 있는 감옥 1~감옥 4의 경우 각 방 문 앞에 있는 스위치에 각각 연결하여, 안에 갇힌 NPC가 스스로 문을 열지 못하도록 할것.
>
> D층~E층에 있는 원자로, 양쪽 문 바깥에 소화기를 하나씩 비치할것. 함장실 좌측에 있는 레버(태그 : reactor_switch)는 원자로와 연결하여, 원자로에 불이 났다면 강제로 원자로를 끄는 레버가 되도록 배선할것.
>

  - 잠수함은 전체 헐 부피의 **7%**가 물이면 중성이다.
  - 항법 단말기가 중립이면 펌프 목표 수위 = `NeutralBallastLevel`이다.
  - 현재 밸러스트는 전체 헐의 **14.16%**다. 그래서 세 단말기 모두 `NeutralBallastLevel="0.494"`로 맞췄다(0.07/0.1416).

- **시작 직후 떠오르는 현상은 게임 고정 동작이다**
  - 라운드 시작 때 `Submarine.NeutralizeBallast()`가 밸러스트를 (중립 수위 − 여분 물/전체 부피) × **0.9**로 채운다. 즉 약 45%다.
  - 전원이 들어오기 전에는 7%보다 물이 적어 떠오른다. 항법 단말기의 "하강 속도"가 −면 상승이다.

## 6. 게임 동작 메모 (게임 소스로 확인한 것 — 다음 작업에 필요한 지식)

소스는 `https://raw.githubusercontent.com/FakeFishGames/Barotrauma/master/<경로>`로 받아 확인했다. 주요 경로:
- `Barotrauma/BarotraumaShared/SharedSource/Items/Components/Power/Powered.cs`
- `.../Items/Components/Machines/Pump.cs`
- `.../Items/Components/Machines/Steering.cs`
- `.../Items/Components/Signal/RelayComponent.cs`
- `.../Items/Components/Signal/Connection.cs`
- `.../SharedSource/Map/Submarine.cs`
- `.../SharedSource/Map/SubmarineBody.cs`
- `Barotrauma/BarotraumaClient/ClientSource/Map/Submarine.cs` (에디터 경고)

**파일 형식**
- `.sub` = gzip XML. 루트 `<Submarine>` 속성: name, dimensions, tier, price, gameversion 등.
- 자식 요소: `Structure`, `Item`, `Hull`, `Gap`, `WayPoint`, `LinkedSubmarine`.
- `rect="x,y,w,h"`: (x, y)는 좌상단, y축은 위가 +. ID는 모든 요소에서 유일하다.
- 아이템끼리의 링크는 `linked="id,id"`. 문↔갭, 산소 발생기↔환풍구, 분해기↔캐비닛, 단말기↔상태 모니터가 모두 이 방식이다.
- **배선**
  - 배선은 별도 `Item`(redwire 등)이다. `<Wire nodes="x;y;x;y…">`가 경로다.
  - 양 끝 아이템의 `ConnectionPanel` 핀 안에 `<link w="배선ID" i="0|1"/>`가 들어간다.
  - 핀 하나당 최대 5개.
- **구조물 크기**
  - `vanilla_templates.json`의 `resW/resH`가 False인 구조물은 지정한 크기를 무시하고 고정 크기로 깔린다.
  - 예: `opbg_researchlab2` → 3760×48 사고.
- **아이템 rect와 Scale**
  - 파일마다 rect w/h와 Scale의 관계가 일관되지 않다.
  - 예: Scale 0.19 튜브 캐비닛도 rect는 87×187로 저장되어 있다.
  - 크기를 판단할 때는 같은 Scale로 쓴 바닐라 예를 기준으로 하고, 사용자에게 에디터 확인을 요청한다.

**헐과 갭**
- 갭이 어느 헐과 이어지는지는 갭 사각형 바로 바깥 1px 지점으로 찾는다(`Gap.FindHulls`).
  - 좌우로 흐르는 문 갭은 `horizontal="true"`, 상하 해치 갭은 `"false"`.
  - 한쪽에 헐이 없으면 바깥과 이어진 갭이다.
- 문과 해치는 `linked`로 자기 갭을 가리킨다.

**전력 (중요)**
- `Powered.ValidPowerConnection`:
  - 두 핀이 모두 전원 핀이어야 한다(`power_in`/`power`/`power_out`).
  - **한쪽이 정션박스나 도킹포트이거나, 한쪽이 출력이고 다른 쪽이 입력일 때만 유효하다.**
  - 그래서 펌프↔펌프, 조명↔조명, 배터리↔배터리 같은 데이지체인은 **전원이 안 들어간다.**
- 많은 장치에 전원을 나눌 때는 바닐라처럼 숨김 **릴레이**를 쓴다.
  - 연결: JB → 릴레이 `power_in`, 릴레이 `power_out` → 장치 여러 개.
  - IsOn=True. 처리량은 `MaxPower`로 정한다(기본 1000).
- 릴레이 신호 동작:
  - `toggle`은 신호 값이 "0"이면 무시한다.
  - `set_state`는 0이 아니면 켠다.
  - `state_out`은 계속 출력한다.
- 배터리: `disable_output` 입력으로 방전을 막는다.

**부력과 밸러스트**
- `SubmarineBody.CalculateBuoyancy`
  - 물 비율 = 연결된(도킹된) 모든 잠수함 헐의 물 / 부피.
  - **0.07이면 중성이다.**
  - 도킹된 셔틀의 헐도 계산에 들어간다.
- `Submarine.NeutralizeBallast`: 라운드 시작 때 실행된다.
  - 밸러스트 헐 판정: `ballast` 태그 펌프가 있는 헐이거나, 방 이름에 "ballast"가 들어간 헐.
  - 채우는 양: (단말기 NeutralBallastLevel − 여분 물/전체 부피) × 0.9.
  - 어느 단말기 값을 쓸지 고르는 코드에 버그가 있어 사실상 마지막 단말기 값을 쓴다. 그래서 **모든 단말기 값을 같게** 둔다.
- `Steering`
  - 중립이면 `velocity_y_out` = (NBL×100−50)×2를 보낸다.
  - 펌프 `set_targetlevel`은 −100~100을 0~100%로 바꾼다. 그래서 중립 수위 = NBL.
  - **전원이 없는 Steering은 신호를 보내지 않는다.**
- `Pump`
  - 목표 수위를 쓰면 유량 = (목표 − 현재%) × 10이다.
  - 연결된(linked) 헐의 수위를 합산한다.
  - 전원이 없으면 물이 움직이지 않는다.

**기타 동작**
- 도킹포트·도킹해치
  - `toggle` 입력으로 도킹/해제한다.
  - `state_out`은 도킹 상태(1/0)를 계속 내보낸다.
- 원자로 `shutdown`은 **어떤 값이 와도** 동작한다. 그래서 필터가 필요하다.
- 버튼과 단말기 신호 버튼(CustomInterface)은 클릭 한 번에 신호를 한 번 보낸다.
- 문 `ToggleWhenClicked="False"`이면 손으로 열 수 없다.
- 분해기
  - 결과물은 링크된 컨테이너에 순서대로 들어간다.
  - `DisplaySideBySideWhenLinked="True"`이면 링크된 UI가 나란히 열린다. 상태 모니터와 항법 단말기도 같은 원리다.
- AI 청소는 `allowcleanup` 태그 컨테이너에서 물건을 꺼낸다.
- 산소 발생기는 환풍구에 배선이 아니라 **링크**로 산소를 보낸다.
- 스폰 포인트 형식:
  - 사람: `<WayPoint spawn="Human" job="captain" idcardtags="id_captain" …/>`
  - 화물: `spawn="Cargo"`
- 에디터 경고 `TooLargeForEndGame`: `dimensions`가 가로 80m 또는 세로 32m를 넘으면 뜬다.

**새 단계 진행 방법**
1. `python3 tools/analyze_sub.py "input/<최신>.sub" circuits`와 `rooms`로 현재 ID와 구조를 파악한다.
2. 새 스크립트를 만든다(예: `tools/build_base7.py`).
   - 패턴: `Sub(load_sub(입력))` → 수정 → `save_sub(root, 출력.sub, build/출력.xml)`.
3. 배선과 게이트:
   - 구조를 다 바꾼 **뒤에** `Wiring(sub, log)`를 만든다. 벽 격자를 그 시점에 계산하기 때문이다.
   - 기존 게이트 칸을 `wr.gate_cells`에 등록해야 겹치지 않는다(`build_base6.py` 참고).
4. 아이템을 지울 때는 그 아이템의 배선(양쪽 핀 link 포함)과 다른 아이템 `linked` 목록의 참조도 지운다(`build_base6.delete_item`).
5. 배경 소품은 `sub.deco_item` 또는 R11 속성으로 만든다. 구조물 크기가 고정인지 `vanilla_templates.json`의 resW/resH로 확인한다.
6. 확인:
   - `python3 tools/check_rules.py <출력.sub>`
   - `python3 tools/render_preview.py <출력.sub> build/preview.png 0.25 [x0,x1,y0,y1] [wires]`
7. 커밋하고 푸시한 뒤 사용자에게 파일을 보내고 보고한다. 지키지 못한 규칙과 확인이 필요한 것을 함께 쓴다.

**참고 자료 위치**
- `히페리온_참고잠수함.zip`을 풀면 `바닐라/`, `말라카이트/` 같은 폴더가 나온다.
- `build_base6.py`의 `ref()` 함수는 `<풀린 폴더>/*/*.sub`에서 요소를 복제해 온다. 실행 인자로 그 폴더를 준다.
- 미리보기 글꼴: `/usr/share/fonts/truetype/nanum/NanumGothicCodingBold.ttf`. Pillow가 필요하다.

**주의**
- 사용자가 에디터로 저장하면 ID가 다시 매겨진다. 예전 ID를 쓰지 않는다.
- 외장과 함장 전용실은 사용자 작품이다. 건드리기 전에 묻는다.
- 헐이나 탱크를 바꾸면 중립 수위를 다시 계산한다.
- 하부 도크에는 헐을 넣지 않는다.
